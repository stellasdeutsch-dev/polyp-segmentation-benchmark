Stage 4. A U-Net we wrote ourselves

The U-Net is the classic model for finding the exact outline of something in a picture. We wrote one from scratch, proved it works exactly like a well-known version, measured what it costs to train on a laptop, and started training it. This page explains each step in plain words.

How a U-Net sees a picture

The left side shrinks the picture step by step to work out what is in it. The right side grows it back to draw where it is, pixel by pixel. Bridges between the two sides carry the fine detail across, so the outline comes out sharp.

Tap or hover a block

Each block is one step. Its height shows how big the picture is at that step, its width how many numbers describe each spot. The sizes are measured from our model with a 256 × 256 input.

How we know our code is right

Writing a model yourself is easy to get slightly wrong. So we compared ours with milesial's U-Net, one of the most widely used versions.

  1. 1Same starting numbersWe copied every one of milesial's 31 million numbers into our model.
  2. 2Same picture inBoth models got exactly the same input.
  3. 3Identical answer outEvery output value matched to the last bit. The training updates matched too, down to rounding.

If even one layer were different, the answers would differ. A test now repeats this check every time the code changes. On the way we also found a bug in milesial's code: its rescue plan for "out of memory" crashes when it runs.

What it costs to train

The paper's U-Net is big: about six times the work per picture of the model in stage 5. On a fanless MacBook Air one full training run takes about 4-7 hours.

How training is going

After every pass over the training pictures, the model is quizzed on 158 pictures it never trains on. The score is Dice: 0 means it found nothing, 1 means a perfect outline.

The five runs

The first three try three learning speeds. The best one is then used twice more with a different random start, to see how much the result depends on luck.

    Mistakes we caught

    • Every test picture scored zeroThe model saw the true outline as 0 and 1, but the grading code expected 0 to 255, so every outline looked empty. The grading code now refuses that format instead of quietly getting it wrong.
    • Two kinds of "Dice at 0.5"For PraNet we measured it on a stretched picture, for our model on the raw output. Before the two share a table, PraNet will be measured the same way as ours.
    • Other work slows training a lotRunning tests during training made one pass take 31 minutes instead of 5. We now report the typical time per pass, which one slow pass cannot spoil.
    • Training stopped twiceOnce it was ended from outside, once the Mac restarted. The model saves itself after every pass, so each time it carried on from the last finished pass.
    • After a stop, the model saw old pictures againA restarted run repeated the same picture order and the same random changes it had used from pass 1. Now a restarted run gets fresh ones, and each run records where it was restarted.

    Questions you should be ready for

    Why write a U-Net yourself instead of using a library?

    To understand every layer and to be able to change it. Matching milesial's version exactly shows the code is right, not just that it runs.

    Where does your U-Net differ from the 2015 paper?

    Three changes, all common today: padding keeps the output the same size as the input, BatchNorm after each convolution makes training stable, and there is no dropout. Size, layers and starting values follow the paper.

    Why train five times?

    Three runs choose the learning speed on the quiz pictures, never on the test. Two more runs with a different random start show how much the score moves by chance. A difference between models only counts if it is bigger than that.

    Why not make it smaller to save time?

    The project asks whether newer models really beat a fair U-Net. A shrunken U-Net would make that question easier to answer the wrong way. The smaller one is still tested, in stage 7, as an extra experiment.

    How do you know the final exam grades the same way as the quiz?

    We graded the quiz pictures with the exam script and got the same score as the training loop, 0.564492 against 0.564491. A test keeps it that way.

    Words on this page

    U-Net
    A model shaped like the letter U: it shrinks a picture, then grows it back into an outline.
    Parameters
    The numbers a model adjusts while it learns. Ours has 31 million.
    Pass (epoch)
    Showing the model all 1,292 training pictures once.
    Learning speed (rate)
    How big a correction the model makes after each mistake. Too big and it jumps around, too small and it learns slowly.
    Random start (seed)
    The random numbers a model starts from. A different seed gives a slightly different result.
    Quiz pictures (validation)
    158 pictures kept aside to pick the best version of the model. Never used to train it.
    Final exam (test)
    Five sets of pictures from different hospitals, used once at the very end.
    Dice
    How well two outlines overlap: 0 is no overlap, 1 is a perfect match.
