Why not just use the papers' numbers

The published results look clear: newer models beat U-Net by about 0.1 Dice on hospitals seen in training and by up to 0.39 on unseen ones. But reading the code showed three reasons those numbers cannot simply be compared.

1

No validation set

PraNet keeps its last epoch. Polyp-PVT tests every epoch on a test folder and keeps the best one, so its reported score is the luckiest of many measurements.

2

A different Dice

The headline "mDice" stretches each prediction to the full range and averages Dice over 256 thresholds. It is not Dice at a threshold of 0.5.

3

Copied, not re-measured

The same model gets 0.709 in one paper and 0.712 in another. Baseline rows travel from paper to paper instead of being run again.

Three ways to produce a mask

Every model in this project is one of three designs. Our ladder climbs through them.

Per-pixel, with a decoder

An encoder shrinks the image into features, a decoder grows them back, and every pixel gets a score. Skip connections carry fine detail across.

Rungs 1 and 2: U-Net from scratch, U-Net with ResNet-34

Mask classification

A set of learned queries each predicts one mask and one label; the final map combines them. It can tell two touching objects apart.

Server stage: Mask2Former, EoMT

Frozen backbone, tiny head

A pretrained model is not trained at all. A single linear layer maps its patch features to classes. It shows how good the features are on their own.

Where the structure loss looks

PraNet weights each pixel by 1 + 5·|avgpool(mask) − mask|. Flat regions get weight 1. At a straight edge the window is half polyp, so the weight is about 3.5; thin or pointed parts go higher, up to 6. Change the window and the strength to see the band move.

What picking the best epoch on the test set does

A model whose true Dice is 0.800 is scored on the test set after every epoch, and the best score is reported. The more epochs you look at, and the smaller the test set, the more the reported number drifts above the truth.

Test set size
0.800True Dice
0.833Reported, best of the epochs
+0.033Inflation

This is an illustration, not a measurement. It assumes each image's Dice varies with a standard deviation of 0.20 and treats epochs as independent, which overstates the effect, since neighbouring epochs are similar. Stage 7 measures the real inflation on our own models.

In the code

The three lines that matter most, each linked to the exact commit we read.

Boundary weights

weit = 1 + 5*torch.abs(F.avg_pool2d(mask, kernel_size=31, stride=1, padding=15) - mask)

The average over a 31×31 window equals the mask itself inside flat regions, so the difference is zero there. Near an edge the window mixes polyp and background, the difference grows, and so does the weight.

PraNet MyTrain.py, line 13

Stretching every prediction

res = (res - res.min()) / (res.max() - res.min() + 1e-8)

Each probability map is stretched to the full 0-1 range before scoring, and Dice is then averaged over 256 thresholds. A badly calibrated model can still score well, so we report Dice at 0.5 next to it.

PraNet MyTest.py, line 37

Choosing the checkpoint on test data

meandice = test(model, test_path, 'test')
...
if meandice > best:
    best = meandice
    torch.save(model.state_dict(), save_path + 'PolypPVT.pth')

test_path defaults to the test dataset folder. The saved "best" model is the one that scored highest on test data, which is the inflation shown in the simulation above.

What can go wrong

  • Leaking video framesResolved in stage 2: the dataset publishes which video each CVC-ClinicDB frame comes from, so validation uses whole videos. The same check showed the benchmark's own CVC-ClinicDB test set shares videos with training.
  • Mixing up the two Dice scoresPutting our Dice at 0.5 next to a published mDice would look like a loss. Every table states which one it shows.
  • A bug in our own metricThat is why our functions are tested against SMP and MONAI, and why stage 3 must reproduce PraNet first.
  • Foundation features that do not transferDINOv3 learned from web photos, not colonoscopy. A weak result for rung 3 would be a finding, not a failure.
  • A laptop that slows downThe Air has no fan and throttles under long load. Latency is measured on a cool machine, and training runs fit short sessions.
  • Trusting copied numbersPublished baselines are shown with their source table, and we re-run the reference ourselves.

Questions you should be ready for

Why not just use the numbers from the papers?

Papers compute Dice differently (averaged over thresholds versus at 0.5, per image versus pooled), and some choose their checkpoint on the test set. Measuring every model with one evaluation script is the only fair comparison.

What is wrong with picking the best epoch on the test set?

It turns the test set into a validation set. The reported number is the maximum of many noisy measurements, which is biased upward. We keep a separate validation split and touch the test sets once.

Why do the unseen hospitals matter more than Kvasir?

A hospital deploys a model on its own equipment. CVC-ColonDB, ETIS and CVC-300 come from other centres and cameras, so they are the closest test of that. The gap between seen and unseen is the real measure of robustness.

What does the structure loss do?

It is BCE plus IoU with extra weight near object edges. Most pixels are easy background or easy interior; the errors that matter are at the boundary, so the loss concentrates there. The 2015 U-Net weight map and Mask2Former's uncertain-point sampling follow the same idea.

Why does nnU-Net beat newer architectures in "Revisited"?

Because the comparison was fair: the same data, the same splits and a well-configured baseline. Many reported gains came from more training, pretraining or a weak baseline, not from the new architecture.

Per-image Dice or pooled Dice?

Pooled Dice treats the test set as one big image, so large polyps dominate. Per-image Dice gives a small missed polyp the same weight as a large one, which matters clinically. We report per image and say so.

Why a frozen backbone with a linear head?

It measures how good the features are on their own. It trains in minutes after one feature-extraction pass and is hard to overfit. If it matches a trained U-Net, the backbone did most of the work.

Why keep EoMT for the server?

The EoMT paper shows the gap to the full Mask2Former pipeline grows for small models: 5.8 PQ with ViT-S against 0.7 with ViT-g. ViT-S is what fits on the laptop, which is exactly where EoMT is weakest.

Glossary

Dice
2·|A∩B| / (|A|+|B|): overlap between predicted and true mask, from 0 to 1.
IoU
|A∩B| / |A∪B|. Never higher than Dice for the same masks.
mDice (PraNet style)
Dice averaged over 256 thresholds after stretching each map to 0-1, then over images.
Boundary IoU
IoU counted only near the edges, within 2% of the image diagonal.
Seen and unseen hospital
Whether images from that centre were in the training data.
Skip connection
A direct link from an encoder level to the decoder level of the same size.
Linear probe
One linear layer trained on frozen features, used to judge the features.
Bootstrap interval
Resample test images many times to see how much the average could move by chance.
